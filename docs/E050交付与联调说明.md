## 给 C：必须新增的存储能力

已核对0.1.9源码，原CountInput仍是`window_start/window_end/entries/exits`，query_counts按旧人次聚合；短时预测点仍是旧窗口模型。0.1.9的任务进度/恢复/失败/读取增强不能视为新画面人数存储已经交付。

请C在自己的目录实现并交付新契约，保留旧数据含义，不做字段重命名迁移：

1. 指标字典登记camera_visible_people、单位“人”、frame/5min和不可累加规则。
2. 分析配置保存ROI、DM-Count权重、抽帧间隔、聚合规则、运行时、设备和模型版本。
3. 可保存逐帧recorded_at/value及5分钟period_start/end/value/sample_count/median，缺值为null而非0；保留source_ids、来源时间和写入时间。
4. 新指标的分析归属校验、有效租约写保护、重复点一致跳过、冲突拒绝、完成发布与任务完成同事务。
5. 按视频和分析读取两粒度结果、录像起止时间、质量与人工帧标注；旧进出标注不能用作画面人数真值。
6. 预测保存/读取未来时点target_time/value、metric、cutoff、训练输入清单、分跨度误差与模型版本，不使用旧direction语义。

本轮E未向旧表写新结果。新schema及迁移编号由C交付后确认；D再绑定load_counts和保存函数。

仍需C交付：获准使用的密集/稀疏视频或帧、固定ROI、来源/授权记录、抽样帧可见人数标签及标注版本；真实预测另需同机位连续长录像。现有16份知识资料已经接收，不再作为“等不到文档”的阻塞理由。

## 给 D：切换0.5.0的具体步骤

1. 安装新版wheel或editable包，替换0.4.0；不要仅靠inspect.signature认为已接通。
2. 按E_SERVICE_CONTRACT.md注入submit_job、load_counts、validate_analysis、knowledge_index_path。没有真实绑定时返回明确依赖/不支持错误，不能绕过校验伪装queued。
3. 统一Worker领取与续租，将knowledge_index/video_analysis派给dispatch_analysis_job；不再导入旧AnalysisWorker。knowledge_reindex由D展开单文档任务。
4. 对知识计算产物真实落盘，通过C同事务写片段、激活与complete_job；提交后发布完整活动索引。API所有进程读取同一个发布路径。重启时可从C活动版本重建发布，恢复未完成的提交后发布动作。
5. C新画面人数存储未到位前，视频保存/读回保持明确不可用；可以独立验收真实模型计算与合成HTTP适配，不能宣称真实端到端视频完成。
6. counts内部读取还需录制起止时间，E验证cutoff位于录像范围内；DHTTP可按已有schema选取公开字段。HTTP对422、409、503及不足状态映射按契约执行。
