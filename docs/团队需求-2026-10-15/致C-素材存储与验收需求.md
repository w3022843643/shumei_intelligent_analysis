# 致 C：素材、存储与验收需求

日期：2026-10-15。发出方：E。主责目录：C 的 `data_foundation/`。

基线为已接收的 C 官方 0.2.0a2 / 迁移 0006；16 份真实公开知识资料已有 E 隔离索引与加载证据。本轮不是要求重新交一批相同资料。正式计数改用 P2PNet，口径为 `camera_visible_people`；旧进出计数不能转换成该指标。

## 本轮请先确认三件事

1. **原视频怎么交给 D Worker**：提供现有真实入口/签名、最小调用样例、可用视频身份及摘要、授权和真实录制时间。若当前不支持或无素材，列出缺口及由谁补齐；不要用上传时间补录制时间。
2. **新人数结果存在哪里、怎么读回**：确认逐帧/5 分钟人数、ROI、模型信息、质量和样本数的实际读写支持。请与 D 一起确定 C 存储与 D 自持存储的边界，给一份一致的支持矩阵；已有能力直接给样例，不默认要求新增迁移。
3. **原文版本从哪里取**：确认 D 应读取的 `document_version` 字段和原文取回入口，帮助 D 消除硬编码 `v1`。本批资料已有，不需重复采集。

请先回传“提交/包/迁移版本 / 视频入口或缺口 / 计数存储支持矩阵 / 原文入口与版本规则”。人工真值与长连续数据作为后续批次，不必等齐才回复。E 收到真实签名后核对计算结果映射，D 负责 HTTP、统一任务分发和正式写库。

## P0：与 D 明确原始视频及文档取回入口

- D 回执称真实视频处理仍受“24 号视频文件接入”阻塞。请与 D 确认原视频资产登记、按 video/asset ID 获取授权文件的方法、真实函数签名和失败行为，并交付可运行样例；本文件不预设 C 已有该接口。
- 视频元数据应包含 source/video/asset/camera 身份、文件摘要、真实录制起止及 UTC 偏移、分辨率、授权记录和展示范围。上传时间不能替代录制时间。
- 明确知识原文 asset 的取回入口及完整性验证，供 D 重建使用。`get_index_artifact_ref` 是索引产物引用，不能当原始文档下载接口；原文不存在时应返回明确缺口。
- 确认 `document_version` 的生成、登记和读取规则；本批固定资料按每份文档自己的 `sha256:<摘要>` 透传。与 D 一起修正硬编码 `v1`，并重新生成版本绑定正确的索引。

## P0：确认新计数和预测的持久化能力

请提供实际支持情况、函数签名、字段样例及读写证据；未支持的项明确列缺口，不用旧 `entries/exits` 字段承载：

- 逐帧人数与帧时刻；完整 5 分钟窗口中位数、窗口起止、有效样本数、质量和缺失原因。
- `video_id/analysis_id`、固定 ROI/机位、`p2pnet`、权重版本、运行时与设备及本次处理来源。
- 预测结果与输入 analysis/时间范围、`cutoff_at`、跨度、模型版本、回测误差、数据不足状态和可空上下界的关联。
- D 自持 analysis/provenance 与 C 存储各自负责哪些字段；跨存储失败时如何避免任务成功但结果不可读，租约如何保护写入及重试去重。

若需迁移，请由 C 发布新版本、迁移说明和回执，不能让 E 私改业务表；是否需要升级以实际接口缺口为依据。

## P1：授权素材、人工真值及连续数据

- 优先交一段可供完整计数联调的固定机位授权视频；另交足够长的连续录像用于 5 分钟聚合和预测，短片不能循环凑历史。
- 协调素材提供者和两位标注/复核人员，准备 sparse/dense/occluded/small_targets 场景、冻结 ROI、逐帧人数及不确定人物记录；C 登记来源与标注版本，E 负责评估，不要求 C 自行训练算法。
- 15/30 分钟预测最低历史点数为 12/24；当前 E 至少需 17/32 个完整连续点形成 3 折验证，仍需实际回测决定可用性。60 分钟暂不开；跨机位、移动/变焦、ROI/模型变化不得无条件拼接。
- 与 D 在隔离 MySQL 库复验旧租约、重试去重和发布/完成事务；E 已提供可运行故障注入参考，不以 E SQLite 结果代替 MySQL 证据。
