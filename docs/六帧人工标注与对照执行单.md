## 怎样人工标注

先只查看frames里的原图，不查看predictions。两人分别按可辨认的人头中心计数，再核对分歧；最终人数写manual_count，未解决的人物写uncertain_people，不把未知当零。标注员/复核员用不同别名，场景填写sparse、dense、occluded或small_targets中实际相符的一类，不为补四类覆盖硬贴标签。

共同确认后填写label_status=reviewed、label_revision非空修订号及上述字段；uncertain_people必须为0才能评分。如果两人尚有分歧，保留pending。id、file、sha256、frame_index、nominal_offset_seconds、prediction_sha256及ROI保持原值。也可以把六个复核人数和别名回传给E，由E整理入标签；不能拿模型输出充当人工真值。

全画面ROI只用于这轮探索；固定机位尚未人工确认，视频绝对录制时间未知，仅记录帧号及相对偏移。此短片已用于推理调试，且相邻帧相关，不是独立holdout，也不能满足正式四类场景覆盖、5分钟聚合或短时预测验收。

## 标注完成后的评分

```powershell
python -X utf8 demo/score_leader_comparison.py
# 标签在另一个位置时：
python -X utf8 demo/score_leader_comparison.py --labels ./artifacts/received-reviewed-labels.json
```

脚本先复验冻结预测、原始PNG、密度图及点文件的摘要，核对标签的帧身份、ROI和预测批次，再检查整数人数、场景和独立复核声明。任一帧待复核，则整个批次保持待标注，MAE均为空；不只挑已标注且表现好的帧评分。文件篡改或输入身份不符直接拒绝。评分输出不能覆盖原图、标签或冻结预测。

全部复核通过后输出两模型总体MAE、分场景MAE、逐帧绝对误差及缺失场景。状态为exploratory_scored，仍不自动批准替换正式模型。人工授权真实性及复核声明需要团队确认，代码不能证明人实际执行了复核。
