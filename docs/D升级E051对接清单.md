## 知识闭环：优先完成

上传处理当前仍以文件名生成 `doc-...`，直接向 E 传旧 metadata。请先登记 C 来源/原件/文档（或使用已登记资料），以 C 的 UUID 和 document_version 构造 metadata.document_id、metadata.document_version。E 不再从文件名推导身份或自行生成 queued 的任务。

submit_job(type,payload) 必须先真实登记、提交，再返回 `{status:"queued",job_id}`；视频另返回真实analysis_id。knowledge_reindex是D管理操作，展开逐文档knowledge_index任务；重建需新索引版本，不能对已经ready的相同版本重复begin_index。

单文档 payload：

```python
payload = {"document_id": c_document_id, "version": index_version,
           "file_path": trusted_staged_path, "metadata": c_document_metadata}
prepared = dispatch_analysis_job("knowledge_index", payload)
```

D 事务/落盘顺序：

1. 领取后及时退出短事务。解析/切分/JSON构建在事务外，D保持心跳。
2. 真实落盘prepared.artifact_bytes，保留SHA256和字节数；索引不可变。
3. 短事务begin_index/write_chunks（按C限制分批），退出提交；片段重传相同内容跳过，不同内容拒绝。
4. 最后短事务activate_index+jobs.complete_job一起提交；任何异常向外传播触发整体回滚。旧租约不能继续发布。
5. 只读取已经提交的活动版本，重新取得已校验引用。对外响应过滤DATA_ROOT、relative_path、租约token、artifact_bytes等内部内容。

## HTTP 层仍有的具体形状差异

| 位置 | D 当前情况 | D 所需调整 |
|---|---|---|
| 录像分析请求 | B/D ROI为`[[x,y],...]`，D直接透传；E为`[{x,y},...]` | 在e_bridge转换ROI，保持B公共契约；透传config用exclude_none=True，PyTorch不带openvino_version=null |
| 缺帧计数 | D CountPoint.value只接受float | 改为float或null，配合unavailable/sample_count=0；不能填0掩盖无样本 |
| 计数分析元数据 | D GET已支持analysis子对象并向前端放顶层 | 保留现有转换；E load_counts内部结果另需video_id、录制起止、完整analysis/ROI和两粒度点 |
| 预测误差 | E用persistence_mae，D SpanValidation用baseline_mae | e_bridge显式映射，保留sample_count，fold_count可新增可选字段；不能丢掉基线对照 |
| 预测点 | E target_time/lower/upper，D已有period_start/end/lower_bound/upper_bound转换 | 复用现有转换，null区间保持null |
| 异常映射 | e_bridge主要捕获Pydantic校验，未映射E新依赖异常 | DependencyUnavailable→503；UnsupportedAnalysis→422；分析未完成→409。产物损坏不得继续旧内存回答 |
| 数值查询 | D目前直接转发ChatContext，没有注入工具 | 服务端识别数值请求并注入受约束metric_query/metric_tool；不能信任用户传入可执行对象 |
| 数值结果 | E额外返回metric_result，D ChatResponse会过滤 | 增加可选metric_result或等价公开溯源结构，保留查询时间、指标、周期和来源 |

E 0.5.1 数值引用会显式包含url/date=null，满足D已有Citation必填可空字段。仅文档问答不需数值工具，证据不足保持原状态。
